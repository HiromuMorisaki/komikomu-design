# ADR 0002: スクレイピング禁止・公式 API のみ使用

## Status

Accepted (2026-05-30)

## Context

EC サイトから商品情報・価格を取得する手段は以下：

1. 公式 API（楽天ウェブサービス、Amazon PA-API、バリューコマース等）
2. スクレイピング（HTML パース）
3. アフィリエイト ASP のフィードデータ

スクレイピングは技術的に可能で、API 制限を回避できる場面もあるが、各 EC サイトの利用規約で禁止されているケースが多い。

## Decision

**コミコムはスクレイピングを一切行わない。商品データの取得手段は公式 API のみに限定する。**

API が提供していない情報（例：レビュー本文、商品ページの動的情報）は **取得しない**。

## Alternatives Considered

### スクレイピングを併用

- **Pro**：API でカバーできない情報も取得可能
- **Pro**：API 申請の手間がない
- **Con**：**多くの EC サイトの利用規約に違反**（Amazon, 楽天市場規約等）
- **Con**：規約違反による **API 利用停止 / アフィリエイト解約 / 法的リスク**
- **Con**：HTML 構造変更でメンテナンスコストが恒常的に発生

### API が出ていない情報も部分的に取得

- **Con**：上記と同じ規約違反リスク
- **Con**：「ここまで OK / ここからダメ」の境界判断が常に必要、長期的に持続不能

## Consequences

### Positive

- 規約遵守によりアカウント・アフィリエイトプログラムの長期安定運用が可能
- 法的リスクの最小化
- HTML 変更によるメンテナンス工数がゼロ
- ユーザーへの信頼性アピール材料になる（「公式 API のみ使用」と明記可能）

### Negative / Trade-offs

- API がカバーしていない情報は取得不可（レビュー、リアルタイム在庫、フラッシュセール等）
- 機能の幅が API 仕様に縛られる
- Amazon PA-API の売上実績要件をクリアするまで Amazon 連携が遅れる

### 実装ルール

- コードベースに `cheerio` / `puppeteer` / `playwright` 等のスクレイピング系ライブラリを **依存に入れない**
- レビュー時にこれらのライブラリ追加を検知したら必ず確認する
- 「API では取れないけどあったら便利」と気付いた情報は、**取らずに済ませる代替設計** を考える
